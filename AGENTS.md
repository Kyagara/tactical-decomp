# AGENTS.md

Guidance for autonomous agents contributing to the **Final Fantasy Tactics (USA)** PSX decompilation. The goal is byte-for-byte identical C89 for the original `SCUS_942.21` executable.

## Project reality

- **Goal:** write C89 that compiles (via the PSYQ toolchain + maspsx) to the *exact same bytes* as `SCUS_942.21`. "Matching" is byte-for-byte, verified by a linker + asm-differ.
- **Not matched ≠ broken:** every function starts as an assembly stub under `rom/extracted/asm/nonmatchings/`. The project builds with all stubs in place (a bootable bin with **0** functions decompiled); replace stubs one at a time and confirm the re-assembled bytes match.
- **Reproducibility first:** never "improve" the logic. Match the original compiler's output exactly - prefer old-style patterns GCC 2.x emits. No comments, no refactor, no modernize.
- **Scope is exe + blob targets:** `main` / `main_2` / `main_3` / `main_4` / `main_5` (per `config/boot.yaml`) plus disc-blob targets (battle, open, wldcore, world, effect, event; configs under `config/blobs/`, with per-file configs in `config/blobs/effect/` and `config/blobs/event/`). Blob work follows the same byte-exact rules via `BLOB=<name>`-scoped targets (`make BLOB=open split/build/compare/decompile/finish`; families with one config per binary take `BLOB=<family>_<stem>`, e.g. `BLOB=effect_E000`). Blob splat configs live ONLY under `config/blobs/`, blob C units are `src/blobs/<family>/*.c`, blob stubs under `rom/extracted/blobs/`. Never add blob segments to `config/boot.yaml`. Path conventions are encoded in `tools/scripts/target.py`.
- **Legal / commit rules:** `rom/` (disc + `rom/extracted/`) and `build/` are never committed (git-ignored, regenerated by `make extract` / `make split`). Committed sources are `src/*.c`, `include/`, and the hand-maintained splat config. The split `rom/extracted/asm/` stubs are also regenerated, never hand-edited. After a successful match, REGENERATE the progress using `make progress` and then commit.

## Environment

- Python tooling lives in a local venv: `tools/.venv/`. Use it explicitly, never a global python. The full tool list (with one-line purposes) is in **Tools** below.
- The MIPS toolchain is **bundled repo-locally** (no system installs): `make toolchain` → `tools/toolchain/` (GCC 2.6.0-psx + binutils); `make deps` → venv + pip deps + submodules.
- **Compiler pin:** the repo is pinned to **GCC 2.6.0-psx**. 2.7.2+ is ruled out (different epilogue delay-slot scheduling → byte mismatch); 2.5.7 lacks `-mgp32`. The Ghidra PSX loader reports the SDK as PSYQ 3.6.10, but the byte-level GCC pin is authoritative. Two scoped exceptions live in the Makefile, not the pin: `src/blobs/open/open_2.c` builds with `FORK_GCC` (gcc-2.7.2-psx, Sony PSYQ-fork codegen) and `src/blobs/world/world_4.c` adds `-fno-omit-frame-pointer`. Full evidence in `docs/PSYQ_COMPILE_FLAGS.md`; never widen either without byte-level proof, and never read the `tools/toolchain/` dir listing as a pin change.

## Compile flags: `-O2 -G0`

Frozen `GCC_FLAGS` = `-O2 -G0 -EL -mgp32 -mno-abicalls -fno-builtin -fno-common`. This applies to **game code and every linked PSYQ library function** (the SDK archives contain zero `%gp_rel` except the allocator trio). The single `%gp_rel` allocator family (`func_8001423C`/`func_80014278`/`func_80014358`) is decompiled with inline `__asm__("... %%gp_rel(...)($gp)")`; `func_80014358` stays a stub. PSYQ library members are identifiable by their Sony `glabel` and a `config/psyq_matches.csv` hit, and are filtered out of `make pick`. Full evidence in `docs/PSYQ_COMPILE_FLAGS.md`.

## Tools

All commands run from the repo root. Python tools use the local venv
(`tools/.venv/bin/python`); `make` targets wrap them. Each entry notes what it
does.

- **Setup:**
  - `make toolchain` - bundles GCC 2.6.0-psx + binutils locally.
  - `make deps` - creates the venv, installs pip deps, checks out the tool submodules.
  - `make extract` - unpacks the disc into `rom/extracted/baserom/`.
  - `make split` - runs splat to emit per-function `.s` stubs.
- **Build & verify:**
  - `make build` - compiles all C units into the exe.
  - `make compare` - byte-diff's the built exe against the baserom.
  - `make context` - regenerates `build/ctx.c` after header changes.
  - `make bin` - reassembles a bootable emulator disc (exe-only).
  - `make format` / `make check-format` - `clang-format` over `src/` + `include/`.
  - `make clean` - full rebuild (only after a toolchain/`GCC_FLAGS` change; exe-scoped clean also wipes the `rom/extracted/asm` split stubs, re-created by `make split`).
- **Decompile workflow:**
  - `make status` / `make pick` / `make cleanstubs` - list/evaluate the next stub to work on.
  - `make decompile FUNC=<f>` - runs m2c to produce C from a stub.
  - `make finish FUNC=<f>` - verifies byte match + asm-differ, then removes the stub.
  - `make progress` - regenerates the README progress section (function counts; no build needed).
- **Hard-tail forensics:**
  - `make permute FUNC=<f>` - brute-forces C variants via decomp-permuter.
  - `make variants FUNC=<f>` - builds a structured variant matrix.
  - `make rtl FUNC=<f>` - dumps GCC 2.6 RTL passes for forensics.
- **Lookup & analysis:**
  - `./tools/mapfile sym_info|first_diff|bss_check` - symbol lookup / first byte diff / BSS-reorder check.
  - `./tools/coddog match|cluster|submatch <f>` - finds duplicate/near-duplicate functions.
  - `tools/scripts/pick_function.py --symbol <f>` - shows one symbol's stub info.
  - `make show FUNC=<f>` - prints the raw asm stub.
  - `tools/scripts/m2c.py` - MIPS→C89 translator (also driven by `make decompile`).
  - `tools/.venv/bin/splat` - the splat splitter (also driven by `make split`).
  - `tools/third_party/asm-differ/diff.py` - instruction-level diff vs target (also `make diff`).
  - `decomp.yaml` (repo root) - project metadata consumed by the mapfile/coddog wrappers.

Naming: stubs and C definitions keep `func_800XXXXX` (vram is `int(name[5:],16)`). Human-readable names live in `config/applied_names.txt` (reference-only, NOT wired into `boot.yaml`; look them up with `rg`), but never relabel stubs (the two-glabel `m2c -f` trap is gone; `m2c -f` is always the file stem now).

## Decompile-a-function loop

1. **Pick** the next function:
   - `make status` (progress + easiest unimplemented stubs, all segments) or `make pick` (list only). `make cleanstubs [SEG=main_4]` lists only cleanly decompilable stubs (single `jr ra`, no embedded `.rodata`).
   - One symbol: `tools/.venv/bin/python tools/scripts/pick_function.py --symbol func_80011BF4`
2. **Decompile to C** (read-only, prints warnings for merged/rodata stubs): `make decompile FUNC=<func>`. Manual: `tools/.venv/bin/python tools/scripts/m2c.py --context build/ctx.c -f <func> rom/extracted/asm/nonmatchings/<segment>/<func>.s`. Regenerate `build/ctx.c` after header changes: `make context`.
3. **Place the C** into `src/<segment>.c`, replacing the corresponding `INCLUDE_ASM("rom/extracted/asm/nonmatchings/<segment>", <func>);` line. main_4/main_5 functions reference main's rodata through globals like `D_80010000` - keep the `extern` declarations from the stubs.
4. **Verify a byte match:** `make finish FUNC=<func>` (removes the stub, clean build, byte-compare, asm-differ; exits 0 only on score 0). Manual equivalent: `pick_function.py --done <func>` → `make clean && make build` → `make compare` → `make diff FUNC=<func>`.
5. **Re-run progress:** `make progress` (regenerates the README Progress section).

The build is incremental (mtime-based); a no-op `make build` is milliseconds. `make clean` is only needed after a toolchain/`GCC_FLAGS` change.

## Hard tails, permute & variant loops

When a function resists a direct match:

- **Allocator-ordering stalemates** → `make permute FUNC=<func>` wraps decomp-permuter (scratch dir `output/scratch/<func>/`, override with `FFT_PERMUTER_SCRATCH`; scored by objdump diff; 0 = perfect). Try cheap `register ... asm("reg")` pins by hand first (see `docs/PERM_TRICKS.md` §1; register-pin caveats in `docs/PSYQ_COMPILE_FLAGS.md`).
- **Matches standalone but not in-file / off-by-one statement** → `make variants FUNC=<func>` (variant matrix) and `make rtl FUNC=<func>` (GCC 2.6 RTL pass dumps + asm-differ rows). Start from `docs/PERM_TRICKS.md` ("When to reach for these").

**Known hard-tails** (keep as stubs): `config/hard_tails.txt` is authoritative - structural thunks (crt0/boot, `$sp`-toucher, jtbl-align divergence, BIOS-thunk families, CARD/BIOS calls, trampolines/padding, hand-written COP0/GTE entries), the merged `%gp_rel` allocator stub (`func_80014358`), and the allocator-ordering stalemate (`func_80017118`). Never force a match on a registered tail.

## Rules for agents

- Only touch `src/main.c` (and `src/main_2.c` / `src/main_3.c` / `src/main_4.c` / `src/main_5.c`, plus blob units `src/blobs/<blob>/*.c` when working a blob with `BLOB=<name>`). Never edit `rom/extracted/asm/nonmatchings/` (or `rom/extracted/blobs/`) by hand (only `pick_function.py --done` or `make split` write them). Never add blob segments to `config/boot.yaml` (blob configs live in `config/blobs/`).
- Keep decompiled code C89 and byte-match-faithful. No `//`, no C99-only constructs, no inline functions, no comments beyond those implied by the original.
- Do not commit `build/`, `rom/` (disc + extracted baserom + split stubs).
- If a function's semantics are genuinely ambiguous or it mixes GTE (`COP2`) access, note it rather than guessing - keep it a stub.
- **Embedded `.rodata` rule:** splat can merge a `.rodata` block above a function body. That rodata is often referenced *only* by its own function, so unlinking the stub with `--done` silently drops it → `.rodata` shrinks → `.text`/`.data` shift → unrelated symbols land off-by-4. Do NOT hand-pick a shifted symbol name. If a rodata piece is referenced only by decompiled-C, add it to `config/symbol_addrs.txt` with `force_not_migration:True` (e.g. `D_80010184 = 0x80010184; // force_not_migration:True`) so splat emits it standalone; then `INCLUDE_RODATA("rom/extracted/asm/nonmatchings/main", D_800XXXX);` in `src/main.c` **at the same position** the function's `INCLUDE_ASM` occupied, and reference it via `extern char D_800XXXX[];`. Every file under `rom/extracted/asm/` must stay reproducible from `make extract` + `make split`.

## Definition of done

- `make build` + `make compare` green on the stub baseline and after every function; the rebuilt bin stays bootable at each step.
- A function is only "matched" when asm-differ reports **0 mismatched instructions** (`make diff FUNC=<func>`).
- Confirm the decompiled C function is byte-for-byte **same length** (same instruction count) as its target; a stale build (`make clean && make build`) masks size shifts that cascade −4 into `.data`/`.text`.

## FAQ

- **Does the disc contain code besides `SCUS_942.21`?** Yes - raw, non-relocatable blobs (`WORLD.BIN`, `WLDCORE.BIN`, `OPEN.BIN`, `EVENT/*.OUT`, `EFFECT/E###.BIN`) loaded into fixed RAM and `jal`led into the exe. They share its RAM globals. Six blob families decompile alongside it (`make BLOB=<name> ...`, e.g. `make BLOB=open ...`); path conventions in `tools/scripts/target.py`. Full inventory in `docs/PSX_REFERENCE.md` §5.2.
- **GTE/COP2 instructions?** splat disassembles them; m2c has no COP2 support. These are LIBGTE library stubs - keep them as stubs (see "Known hard-tails"). Match via inline `__asm__` only if required.
- **m2c guesses types / function too big?** m2c has no DWARF; pass `--context build/ctx.c` and hand-tune `func_*` params. For pathological CFGs use `--gotos-only` / `--no-unk-inference`.
